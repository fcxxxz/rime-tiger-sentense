## 词表先验消融（2026-11-12，负结果归档）

背景：125 错句中 86% 词表无票（hz 词表多字词仅 102 条），验证「喂真词库」假设。

- **设置**：zrm/flypy 240 万词文本 → 虎码全码形（2 键/字，每字取最优码），第 4 列权重喂梯度，`/tmp/build_word_lexicon.py` 生成、仅 /tmp 消融
- **125 错句修复**：0 → 18（top20 万）→ **22（top100 万）**；词边权重/梯度拉满无增益
- **6250 句切片净效果**：全量 100 万词 **−13**；只留 2~3 字词 −8；＋text_lexicon 减半 −5；top20 万·2~3 字词 **−3**——全负
- **机制**（键流级实证）：词票挪动 beam → 段分界挪移，合法次优码形反超最优码形
  （栋 `eryx` 反超 `ery`，朱裳→啊舌衣）；`木兰无长兄→木兰` 类为基准工装尾段
  重建 artifact（wrong=0，非引擎截尾）
- **结论**：全局平票词先验死路。带语境 word_scorer 理论上可避开回退，但全部
  可修复量 22/50000 ≈ **+0.044pp**，收益上限小、成本高，暂缓；剩余错误预算
  更值得花在上屏锁死类（35 句 ≈ 0.07pp，纯策略）与用户学习层自愈
- 产物：`/tmp/tiger-hz-lvyww-50k-20261111/wp-*`（driver-wordprior.lua 可复用）

## 提前上屏门槛消融（2026-11-12，悬崖实证）

- 锁死类上限：early_commit 全关 → **27/125 修复**（wrong=1 的 35 句救回 25），
  折合全量 ≈ +0.054pp
- 但门槛是**硬悬崖**：0.99（现行）= 30% 上屏率；0.992 / 0.995 / 0.999 /
  全关 **全部**＝ 0 上屏、句尾残留 1.5→12.2 字。置信度分布在 (0.99, 0.999)
  无质量，不存在甜点位
- 结论：这 +0.05pp 拿不到配置层，钥匙在引擎「封边判据」（错上屏＝判据
  被骗过时提交），属结构改动；门槛调参路线关闭

## Qwen 门控重排·10 万句全量验证（2026-11-12 12:00，负结论归档）

引擎＝含「同码整段单字档位序优先」修复（蛰@ukic）的 staging dylib；
语料 corpus-100k.tsv（seed 20261111 重抽，与 50k 无包含）；
打分＝Qwen2.5-0.5B/1.5B-MLX-4bit，complete 候选 sum_token_logp。

- **耗时**：导出 8 分片×12500 句每片 ~24s（整段解码一次/句）；Qwen
  打分 0.5B ~10.7ms/条、1.5B ~25ms/条（M 系列 GPU）
- **触发率**：τ=4.5 门 2.63%（2629/10万）；margin<6 共 3.52%
- **单门 τ=4.5（50k 抽样外推的配置）：修复 121 / 破坏 183 / 净 −62，
  准确率 99.81%→99.75% —— 否决**。抽样失败原因：50k 样本触发正确句
  仅 12 例 0 破坏；全量 2459 例触发正确句破坏 183（7.4%）——小样本运气
- **(τ,δ) 双门网格**（δ=Qwen 对引擎首选的优势差，只统计「过门且 Qwen
  想改」的行）：
  - 0.5B 最优 τ=2,δ=2：修 78 / 破 33 / **净 +45**
  - 1.5B 最优 τ=2.5,δ=2：修 97 / 破 37 / **净 +60**；τ=2,δ=3：修 80/破 22/净 +58
  - 任何配置破坏压不到零；1.5B 修复率更高（81% vs 65%）但破坏同源
- **判定**：这条线现实上限 ≈ **+0.05~0.06pp**（99.81→99.87）且带
  20~40 破坏/10万，与封边判据（+0.054pp，无运行时成本）、带语境词分
  （+0.044pp 上限）同量级——重排不再突出。部署成本（MLX 常驻 ~1GB
  或蒸馏）不成比例，**搁置**；若引擎侧封边做完仍要攻，优先重训蒸馏
  打分器压破坏率，而不是调门
- 产物：/tmp/full-rerank/、/tmp/full_validate.py、/tmp/rescan_grid.py

### 重排结构对决（同 100k 触发域，用户「短码优先」质疑驱动）

用户案例 求收我做小弟：正确=求(fk)+收(ih) 双最优短码 vs 救(fkih 白名单
合法长码) 两字并一；引擎首选正确但 **margin 仅 0.68 nats**（码形最优无
独立加分项，纯三元弱偏好）；Qwen 原始差 **18.42 nats** 偏向 救我做小弟。

| 结构 | 修复/破坏/净 | 求收句 |
|---|---|---|
| 替换式（Qwen argmax） | 121/183/−62 | 死 |
| z 融合 λ=0.5 | 89/40/+49 | 死（z 长尾把 0.68 压成 0.12σ） |
| **top-2 原始差对冲 β×引擎差**（0.5B, β=3） | 82/26/**+56** | 死（18.42≫3×0.68） |
| **同上 1.5B, β=3** | 97/25/**+72** | 死 |

- **最优配置：1.5B top-2 对冲 β=3 → +72/10万（99.81→99.88，破坏 25）**
- 求收类在任意重排结构下都救不回：病灶在引擎侧——对「每字最优码形解析」
  没有显式先验。要在重排时代保留短码优先，需引擎给非最优码形用法加
  罚分（如每字 −γ nats），属组句评分的结构项，归引擎线
- 产物：/tmp/full-rerank2/（带引擎分）、/tmp/fusion_scan.py、/tmp/top2_hedge.py

### 错判病理与打分口径（用户质疑驱动的拆解）

sum_token_logp **对 token 数求和，天然偏爱字少的候选**：高总(4tok)/墙(3tok)
错句白赚 10.2 nats，而均分口径对句反而好 +0.89——用户点名的「不可理解」
错判（过与不过→湃不过、高总→墙、求收→救）3/4 是长度偏置，非 Qwen 语义
判断（仅 季女/意妾 例是 1.5B 真弱点：妾 生僻 token 被罚）。

- 均分口径重排（1.5B·β=1）：修 55/破 25/净 **+30**——破坏大减但全局净效果
  反低于 sum 版（+72）：**偏置两头挣钱（并字候选在错句侧也常是该翻的），
  单修打分口径亏**
- 正确路线：γ 码形先验在引擎侧挡掉并字候选（拟/救/囱/墙 类根本不进 top-2），
  sum 的长度偏置失去作恶对象；打分口径之争等 γ 落地后再标定
