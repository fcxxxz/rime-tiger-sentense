# 终案压力测试：1 万句碰撞字分层语料三臂对照（2026-11-11）

## 语料设计

- 句池：fenci 全量（1,327 万句）中含碰撞字（26 一简字 ∪ 14 碰撞首选字）的可编码句
- **分层抽样**（seed 20261112）：14 个碰撞首选字（皇/题/存/近/吐/敌/络/轼/羊/匕/审/汽/者/强 + 办/首/种/…）
  每字定向抽 ~600 句，补随机至 10,000 句——把随机语料里样本太小的字（办 79→605、皇 24→626、
  吐 8→605）撑到可分辨的量级
- 三臂同句集逐句配对：base / compete（全注入）/ inject2（终案，撤 sh/xd/ho）
- 已知盲区：11 个一简字（在/要/到/不/了/人/大/也/可/而/行）在 base 表中**没有任何
  rank 1 的 ≥2 码**（如 在=n+nggt(r2)、要=vb…），组句不可编码，含它们的句子被三臂
  共同排除——这些字的注入收益（0→可组句）本基准无法计量，只能看到其对码位首选字的伤害

## 结论

1. **终案兑现**：撤注的 3 对（办/首/种、说/和/道）在 8 倍样本下全部回到 base 水平，
   inject2 比 compete +0.80pp，且一简字侧也更好（撤注消除了错句的邻位污染）。
2. **剩余代价的本质**：保留对的伤害全部集中在「一简字字频极高 + 码位首选字极稀」的对
   （在#6/存、的#1/皇、中/吐、就/羊、来/敌）——这是频次悬殊下语言模型的系统性行为，
   不可用全局罚分修复（罚分扫描已证伪）。但这些首选字在**真实分布**里极稀
   （随机 1 万句合计 ~90 次、实际损失 ~4 字），压力语料只是把它们放大了 8~60 倍。
3. **真实分布下的最终数字不变**：inject2 = 99.17%（−0.20pp）换省键 4.43%。
   若把 ng/vb/yp（在/要/到——收益无法计量、只有伤害可见）也撤掉，碰撞合计可再回收
   ~−0.8pp（存/匕/轼），代价是这 3 个字失去组句 2 码——**不建议**，它们恰恰是
   注入后才能组句的字。
4. 附带发现：base 表 11 个一简字无 rank1 ≥2 码（组句不可编码，需 1 键+早提交断流），
   注入是它们获得连续组句能力的唯一路径。

## 复现

- 语料：分层抽样脚本（seed 20261112，每碰撞首选字 600 句定向 + 随机补满）
- 运行：`driver.lua stress-{base,compete,inject2}`（8 分片 × 1250 句 × 3 臂）
- 数据：staging 目录 `stress-*-*.tsv`、`corpus-stress-*.tsv`
