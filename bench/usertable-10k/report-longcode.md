# 一简字不用二码打法：准确度差距对照（2026-11-11）

## 设计

三臂同句集逐句配对，隔离「二码打法本身」的代价：

| 臂 | 表 | all_ranks | 一简字打法 |
|---|---|---|---|
| base | 原表 | false | 长码（3/4 码） |
| 不用二码 | inject2（规则位注入） | true | **长码**（与 base 同一份语料） |
| 用二码 | inject2（规则位注入） | true | 2 码（的=ue、在=ng、要=vb、到=yg…） |

## 结果

| 语料 | base | 不用二码（长码） | 用二码（终案） |
|---|---:|---:|---:|
| 随机 1 万句 | **99.37%** | 99.02% | **99.18%** |
| 压力 1 万句 | **99.06%** | 97.03% | 96.94% |
| 随机省键 | — | 0 | **−4.43%（12,366 键）** |

配对（随机）：长码/二码 = 长码独错 4 句、二码独错 20 句——**二码打法净修好 16 句**。

## 两个发现

**1. 「不用二码」避不开碰撞——伤害与打法无关。**
碰撞发生在注入的码位上，而码位主人本来就要打那些码：「集」的首选码就是 `ue`，
「近」就是 `tu`。注入表在，的@ue 就参与竞争，无论一简字自己打几码：
长码臂里 集 89.5%、近 96.9%，与二码臂逐字相同。

**2. 长码打法自身制造额外切分歧义（随机语料 −0.16pp）。**
的=uni 这类长码延长了歧义窗口，跨界切分错误反而变多：
- #587 「…的话的呢」→ 长码「…的**尾**」、二码正确
- #538 「是周**和**王捐的」→ 长码「是周**调**王捐的」
- #1881 「目的**哒**」→ 长码「目的**达**」
- #2570 「瓜瓤全部」→ 长码「尘器轮玉」（的 的长码位移整句切分）

反向案例（二码独错 4 句）是典型碰撞：#94 「收**的**都」→「收**集**都」。

## 结论

既然注入表是规则语义（在/要/到/的 的规则位），「不用二码」不是可行的中间档：
随机语料上比用二码**更差**（99.02% vs 99.18%），压力语料上打平（−0.09pp）。
**用二码**：随机 −0.19pp（vs base）换 4.43% 省键，且比不用二码还多修 16 句。

## 复现

`driver.lua inject2long / stress-inject2long`（inject2 表 + all_ranks=true + base 语料），
staging 目录 `inject2long-*.tsv`、`stress-inject2long-*.tsv`。
